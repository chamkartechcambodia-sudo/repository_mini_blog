Introduction

The whole course revolves around one app — MiniBlog (a single screen: a list of posts + a Refresh button). Data comes from JSONPlaceholder, is stored in Room, and the UI observes Room through LiveData (the single source of truth is Room).

On branch 00-starter, three networking/RecyclerView files are left empty as // TODO. Your job is to fill them (Step 1) and then refactor toward the Repository pattern.

Tip: each step corresponds to a git branch, and the diff between two adjacent branches IS the lesson. If you get stuck, check out the completed answer with git checkout 01-no-repository (…02, 03, 04), or compare with git diff 00-starter..01-no-repository.
Convention in this guide: for each file, replace the ENTIRE file content with the code shown (unless it says "add these lines"). Keep the package com.example.miniblog line at the top.

Step 1 Make the app run → 01-no-repository

Goal: fill the three stub files (networking + adapter), create PostViewModel.kt, and wire up MainActivity.kt. After this step, tapping Refresh downloads posts and shows them.

ApiService.kt EDIT — declare the endpoint

Define the network call: fetch the list of posts.

package com.example.miniblog

import retrofit2.http.GET

interface ApiService {

    @GET("posts")
    suspend fun getPosts(): List<Post>
}
Why: @GET("posts") is joined with BASE_URL to form .../posts. The suspend keyword lets us call it from a coroutine (in the ViewModel) without blocking the UI.

RetrofitClient.kt EDIT — build Retrofit + Moshi

package com.example.miniblog

import com.squareup.moshi.Moshi
import com.squareup.moshi.kotlin.reflect.KotlinJsonAdapterFactory
import retrofit2.Retrofit
import retrofit2.converter.moshi.MoshiConverterFactory

object RetrofitClient {

    const val BASE_URL = "https://jsonplaceholder.typicode.com/"

    private val moshi: Moshi = Moshi.Builder()
        .add(KotlinJsonAdapterFactory())
        .build()

    val api: ApiService = Retrofit.Builder()
        .baseUrl(BASE_URL)
        .addConverterFactory(MoshiConverterFactory.create(moshi))
        .build()
        .create(ApiService::class.java)
}
Why: Moshi uses its reflection adapter (KotlinJsonAdapterFactory), so NO annotation processor is needed to turn JSON into a Post. Retrofit.create(...) generates the implementation of the ApiService interface.

PostAdapter.kt EDIT — show the list

package com.example.miniblog

import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import android.widget.TextView
import androidx.recyclerview.widget.RecyclerView

class PostAdapter : RecyclerView.Adapter<PostAdapter.PostViewHolder>() {

    private var posts: List<Post> = emptyList()

    /** Replace the whole list and redraw. (DiffUtil is a later optimization.) */
    fun updatePosts(newPosts: List<Post>) {
        posts = newPosts
        notifyDataSetChanged()
    }

    class PostViewHolder(itemView: View) : RecyclerView.ViewHolder(itemView) {
        val titleText: TextView = itemView.findViewById(R.id.titleText)
        val bodyText: TextView = itemView.findViewById(R.id.bodyText)
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): PostViewHolder {
        val view = LayoutInflater.from(parent.context)
            .inflate(R.layout.item_post, parent, false)
        return PostViewHolder(view)
    }

    override fun onBindViewHolder(holder: PostViewHolder, position: Int) {
        val post = posts[position]
        holder.titleText.text = post.title
        holder.bodyText.text = post.body
    }

    override fun getItemCount(): Int = posts.size
}
RecyclerView refresher: onCreateViewHolder inflates one row from item_post.xml; onBindViewHolder puts a Post's data into that row; getItemCount returns the number of rows. updatePosts lets the Activity push new data in.

PostViewModel.kt CREATE — a ViewModel that holds api + dao

Create a new file in the same folder java/com/example/miniblog/.

package com.example.miniblog

import android.app.Application
import androidx.lifecycle.AndroidViewModel
import androidx.lifecycle.LiveData
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.launch

class PostViewModel(application: Application) : AndroidViewModel(application) {

    private val dao = AppDatabase.getInstance(application).postDao()
    private val api = RetrofitClient.api

    /** The UI observes this. Single source of truth = Room. */
    val posts: LiveData<List<Post>> = dao.getAllPosts()

    /** Fetch from the network, then save into Room. The LiveData above updates by itself. */
    fun refresh() {
        viewModelScope.launch {
            try {
                val fetched = api.getPosts()
                dao.insertPosts(fetched)
            } catch (e: Exception) {
                e.printStackTrace()
            }
        }
    }
}
This is the "no Repository" anti-pattern: the ViewModel must know both how to call the network and how to store to the DB, and it needs Application (via AndroidViewModel) to open Room. Step 2 cleans this up.

MainActivity.kt EDIT — wire it up

package com.example.miniblog

import android.os.Bundle
import android.widget.Button
import androidx.activity.viewModels
import androidx.appcompat.app.AppCompatActivity
import androidx.recyclerview.widget.LinearLayoutManager
import androidx.recyclerview.widget.RecyclerView

class MainActivity : AppCompatActivity() {

    private val viewModel: PostViewModel by viewModels()
    private val adapter = PostAdapter()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val recyclerView = findViewById<RecyclerView>(R.id.postsRecyclerView)
        recyclerView.layoutManager = LinearLayoutManager(this)
        recyclerView.adapter = adapter

        // Observe Room (through the ViewModel): when the posts table changes -> redraw the list.
        viewModel.posts.observe(this) { posts ->
            adapter.updatePosts(posts)
        }

        // Tap Refresh -> ViewModel fetches from network -> saves to Room -> LiveData updates the UI.
        findViewById<Button>(R.id.refreshButton).setOnClickListener {
            viewModel.refresh()
        }
    }
}
Why by viewModels() works here: PostViewModel is an AndroidViewModel, so the default factory supplies the Application automatically.
✔ Verify Step 1: Run the app on an emulator (API ≥ 24) → tap Refresh → the list of posts (title + body) appears. Close and reopen the app: the data is still there (it was saved to Room).

Step 2 Extract the Repository → 02-repository

Goal: move the data logic into a Repository class so the ViewModel slims down to just coordinating.

PostRepository.kt CREATE

package com.example.miniblog

import androidx.lifecycle.LiveData

class PostRepository(
    private val api: ApiService,
    private val dao: PostDao
) {
    /** Single source of truth = Room. */
    val posts: LiveData<List<Post>> = dao.getAllPosts()

    /** Fetch from the network, save into Room. */
    suspend fun refresh() {
        val fetched = api.getPosts()
        dao.insertPosts(fetched)
    }
}
Why: the Repository now owns the two data sources (network + DB) and exposes a clean API (posts + refresh()). The rest of the app no longer needs to know where data comes from.

PostViewModel.kt EDIT — becomes a plain ViewModel

package com.example.miniblog

import androidx.lifecycle.LiveData
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.launch

class PostViewModel(private val repository: PostRepository) : ViewModel() {

    val posts: LiveData<List<Post>> = repository.posts

    fun refresh() {
        viewModelScope.launch {
            try {
                repository.refresh()
            } catch (e: Exception) {
                e.printStackTrace()
            }
        }
    }
}
Compared to Step 1: the ViewModel no longer touches api/dao — it just delegates to the repository. But because it takes a PostRepository in its constructor, the default by viewModels() can no longer build it → see MainActivity.

MainActivity.kt EDIT — temporary inline factory

package com.example.miniblog

import android.os.Bundle
import android.widget.Button
import androidx.activity.viewModels
import androidx.appcompat.app.AppCompatActivity
import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.recyclerview.widget.LinearLayoutManager
import androidx.recyclerview.widget.RecyclerView

class MainActivity : AppCompatActivity() {

    // We extracted a Repository, but the slim ViewModel needs it in its constructor. There is no
    // factory yet, so for now we build it BY HAND with an inline factory — a bit clunky; Step 3
    // will clean it up.
    private val viewModel: PostViewModel by viewModels {
        val dao = AppDatabase.getInstance(applicationContext).postDao()
        val repository = PostRepository(RetrofitClient.api, dao)
        object : ViewModelProvider.Factory {
            @Suppress("UNCHECKED_CAST")
            override fun <T : ViewModel> create(modelClass: Class<T>): T =
                PostViewModel(repository) as T
        }
    }

    private val adapter = PostAdapter()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val recyclerView = findViewById<RecyclerView>(R.id.postsRecyclerView)
        recyclerView.layoutManager = LinearLayoutManager(this)
        recyclerView.adapter = adapter

        viewModel.posts.observe(this) { posts ->
            adapter.updatePosts(posts)
        }

        findViewById<Button>(R.id.refreshButton).setOnClickListener {
            viewModel.refresh()
        }
    }
}
Deliberate pain point: the ViewModel construction code "leaks" into the Activity. This is exactly the problem Step 3 (Factory + Application) solves.
✔ Verify Step 2: the app runs exactly like Step 1 (this is a refactor, behaviour is unchanged).

Step 3 Factory + Application (manual DI) → 03-factory-di

Goal: gather construction into one place (the Application) and use a reusable ViewModelFactory. No Hilt.

MiniBlogApplication.kt CREATE

package com.example.miniblog

import android.app.Application

class MiniBlogApplication : Application() {

    val database by lazy { AppDatabase.getInstance(this) }

    val repository by lazy { PostRepository(RetrofitClient.api, database.postDao()) }
}
Why: the Application is the "composition root" — the single place that builds the database + repository and shares them app-wide. by lazy = create on first use, then reuse.

PostViewModelFactory.kt CREATE

package com.example.miniblog

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider

class PostViewModelFactory(
    private val repository: PostRepository
) : ViewModelProvider.Factory {

    @Suppress("UNCHECKED_CAST")
    override fun <T : ViewModel> create(modelClass: Class<T>): T =
        PostViewModel(repository) as T
}

AndroidManifest.xml EDIT — register the Application

Add the android:name attribute to the <application> tag:

<application
    android:name=".MiniBlogApplication"
    android:allowBackup="true"
    android:icon="@mipmap/ic_launcher"
    android:label="@string/app_name"
    android:supportsRtl="true"
    android:theme="@style/Theme.MiniBlog">

MainActivity.kt EDIT — simplify

Remove the inline factory; replace the ViewModel declaration with:

private val viewModel: PostViewModel by viewModels {
    PostViewModelFactory((application as MiniBlogApplication).repository)
}

Also delete the two now-unused imports: androidx.lifecycle.ViewModel and androidx.lifecycle.ViewModelProvider. The onCreate body stays the same as Step 2.

Why: building the repository now lives in the Application, and building the ViewModel lives in the Factory. The Activity just asks for a ViewModel built from the shared repository — clean and reusable. This is manual dependency injection.
✔ Verify Step 3: the app still runs the same; MainActivity is noticeably shorter.

Step 4 Interface + Fake + Test → 04-testable

Goal: make the Repository an interface so it can be swapped for a fake in tests — letting us unit-test the ViewModel without an emulator, network, or Room.

PostRepository.kt EDIT — make it an interface

package com.example.miniblog

import androidx.lifecycle.LiveData

interface PostRepository {
    val posts: LiveData<List<Post>>
    suspend fun refresh()
}

DefaultPostRepository.kt CREATE — the real implementation

package com.example.miniblog

import androidx.lifecycle.LiveData

class DefaultPostRepository(
    private val api: ApiService,
    private val dao: PostDao
) : PostRepository {

    override val posts: LiveData<List<Post>> = dao.getAllPosts()

    override suspend fun refresh() {
        val fetched = api.getPosts()
        dao.insertPosts(fetched)
    }
}

MiniBlogApplication.kt EDIT — build the Default impl

Change the repository declaration to build DefaultPostRepository but typed as the interface:

val repository: PostRepository by lazy {
    DefaultPostRepository(RetrofitClient.api, database.postDao())
}

src/test/java/com/example/miniblog/FakePostRepository.kt CREATE

Note: this file lives in the test folder (src/test/java/...), not src/main.

package com.example.miniblog

import androidx.lifecycle.LiveData
import androidx.lifecycle.MutableLiveData

class FakePostRepository : PostRepository {

    val postsData = MutableLiveData<List<Post>>()
    var refreshCalled = false

    override val posts: LiveData<List<Post>> get() = postsData

    override suspend fun refresh() {
        refreshCalled = true
    }
}

src/test/java/com/example/miniblog/PostViewModelTest.kt CREATE

package com.example.miniblog

import androidx.arch.core.executor.testing.InstantTaskExecutorRule
import org.junit.Assert.assertEquals
import org.junit.Rule
import org.junit.Test

class PostViewModelTest {

    // Lets LiveData run synchronously on the test thread (instead of Android's main thread).
    @get:Rule
    val instantTaskExecutorRule = InstantTaskExecutorRule()

    @Test
    fun viewModel_exposesPostsFromRepository() {
        val fake = FakePostRepository()
        val viewModel = PostViewModel(fake)

        viewModel.posts.observeForever { }
        val sample = listOf(
            Post(id = 1, userId = 1, title = "Hello", body = "World")
        )
        fake.postsData.value = sample

        assertEquals(sample, viewModel.posts.value)
    }
}
Why it's testable now: because PostViewModel depends on the interface PostRepository, we can hand it a FakePostRepository (no network, no DB) and assert that the ViewModel exposes the repository's LiveData.

Verify & troubleshooting

  • The app shows no data on launch: that's by design — Room is empty at first. Tap Refresh to load.
  • Network won't load: make sure the emulator has Internet; the INTERNET permission is already in the Manifest.
  • Gradle sync error about "kotlin.sourceSets": the project already sets android.disallowKotlinSourceSets=false in gradle.properties so KSP 2.2.10 works with AGP 9's built-in Kotlin. Do not remove that flag.
  • notifyDataSetChanged() warning: just a lint warning (DiffUtil is a later optimization) — it does not break the build.
  • Test can't find InstantTaskExecutorRule: you haven't added androidx.arch.core:core-testing in Step 4 — sync Gradle again.
